:toc: left

== Overview

The `pkg/core` package provides built-in Scheme procedures organized into subpackages by category. It follows a modular design where each subpackage defines related operations.

Each Go module in `pkg/core/` has a corresponding Scheme stub file in `core/` that documents the API.

== Package Structure

----
pkg/core/
├── core.go             # Main entry point, aggregates all subpackages
├── builtin/            # Builtin operations (aryth, cmp, conv)
│   ├── builtin.go      # Aggregates builtin definitions
│   ├── aryth.go        # Arithmetic operations
│   ├── cmp.go          # Comparison operations
│   └── conv.go         # Conversion operations
└── math/               # Mathematical operations
    └── math.go

core/                   # Scheme definition stubs
├── builtin/
│   ├── aryth.scm       # Arithmetic stubs
│   ├── cmp.scm         # Comparison stubs
│   └── conv.scm        # Conversion stubs
└── math/
    └── math.scm        # Math stubs
----

== Main Package

=== Loading Core Definitions

The main `core` package provides a function to get all built-in definitions:

[source,go]
----
// All returns all built-in definitions
func All() []mem.Definition
----

=== Usage

Core builtins are loaded automatically when creating a new evaluator:

[source,go]
----
import (
    "github.com/Vallghall/schego/pkg/eval"
)

// Builtins are loaded automatically
evaluator, err := eval.New()
if err != nil {
    // Handle error
}
----

For manual loading (e.g., custom configurations):

[source,go]
----
import (
    "github.com/Vallghall/schego/pkg/core"
    "github.com/Vallghall/schego/pkg/eval"
)

state := eval.NewState()
state.LoadBuiltins(core.All)
evaluator := eval.NewWithState(state)
----

== Builtin Subpackage

The `builtin` subpackage provides core operations: arithmetic, comparison, and conversion.

=== Arithmetic Operations (aryth.go)

[cols="1,1,3"]
|===
| Name | Arity | Description

| `+`
| variadic
| Sum of all arguments (0 with no args)

| `-`
| 1+
| Negation with 1 arg, subtraction with 2+

| `*`
| variadic
| Product of all arguments (1 with no args)

| `/`
| 1+
| Reciprocal with 1 arg, division with 2+

| `modulo`
| 2
| Integer remainder (Scheme semantics)

| `abs`
| 1
| Absolute value

| `min`
| 1+
| Minimum of arguments

| `max`
| 1+
| Maximum of arguments
|===

=== Comparison Operations (cmp.go)

[cols="1,1,3"]
|===
| Name | Arity | Description

| `=`
| 2+
| Numeric equality (all equal)

| `<`
| 2+
| Strictly increasing

| `>`
| 2+
| Strictly decreasing

| `\<=`
| 2+
| Non-decreasing

| `>=`
| 2+
| Non-increasing

| `zero?`
| 1
| True if argument is zero

| `positive?`
| 1
| True if argument is positive

| `negative?`
| 1
| True if argument is negative

| `eq?`
| 2
| Identity comparison (pointer/symbol ID)

| `equal?`
| 2
| Structural equality

| `not`
| 1
| Boolean negation
|===

=== Conversion Operations (conv.go)

[cols="1,1,3"]
|===
| Name | Arity | Description

| `number->string`
| 1
| Convert number to string

| `string->number`
| 1
| Parse string as number (#f if invalid)

| `symbol->string`
| 1
| Get symbol name as string

| `string->list`
| 1
| Convert string to list of chars

| `list->string`
| 1
| Concatenate list of strings

| `integer->char`
| 1
| Unicode code point to character

| `char->integer`
| 1
| Character to Unicode code point
|===

== Examples

=== Arithmetic

[source,scheme]
----
(+ 1 2 3)           ; => 6
(+)                  ; => 0
(- 5)                ; => -5
(- 10 3 2)           ; => 5
(* 2 3 4)            ; => 24
(*)                  ; => 1
(/ 2)                ; => 0.5
(/ 24 2 3)           ; => 4
(modulo 10 3)        ; => 1
(abs -5)             ; => 5
(min 3 1 4 1 5)      ; => 1
(max 3 1 4 1 5)      ; => 5
----

=== Comparison

[source,scheme]
----
(= 1 1 1)            ; => #t
(< 1 2 3)            ; => #t
(> 3 2 1)            ; => #t
(<= 1 1 2)           ; => #t
(zero? 0)            ; => #t
(positive? 5)        ; => #t
(negative? -5)       ; => #t
(not #f)             ; => #t
(eq? 'a 'a)          ; => #t
(equal? '(1 2) '(1 2)) ; => #t
----

=== Conversion

[source,scheme]
----
(number->string 42)        ; => "42"
(string->number "3.14")    ; => 3.14
(symbol->string 'hello)    ; => "hello"
(string->list "abc")       ; => ("a" "b" "c")
(list->string '("a" "b"))  ; => "ab"
----

== Creating New Core Modules

=== Step 1: Create Go Implementation

For a new module in `pkg/core/`:

[source,go]
----
// pkg/core/mymodule/mymodule.go
package mymodule

import "github.com/Vallghall/schego/pkg/mem"

func Definitions() []mem.Definition {
    return []mem.Definition{
        {Name: "my-proc", Value: mem.NewPrimitive("my-proc", 1, myProc)},
    }
}

func myProc(args []mem.Object) (mem.Object, error) {
    // Implementation
    return mem.Void, nil
}
----

=== Step 2: Register in core.go

Update `pkg/core/core.go`:

[source,go]
----
import (
    "github.com/Vallghall/schego/pkg/core/mymodule"
    // ...
)

func All() []mem.Definition {
    var defs []mem.Definition
    // ...
    defs = append(defs, mymodule.Definitions()...)
    return defs
}
----

=== Step 3: Create Scheme Stub

Create `core/mymodule/mymodule.scm`:

[source,scheme]
----
;;; Schego Core Library - My Module
;;; Actual implementations are in Go: pkg/core/mymodule/mymodule.go

;;; My procedure
;;; (my-proc x) -> result
;;; Description of what it does.
(define my-proc
  "Implemented in Go: description.")
----

== Primitive Function Signature

All primitive functions must match the `mem.PrimitiveFunc` signature:

[source,go]
----
type PrimitiveFunc func(args []Object) (Object, error)
----

=== Error Types

Use appropriate error types from `pkg/mem`:

[source,go]
----
// Type mismatch
mem.NewTypeError(mem.TypeNumber, arg.Type(), "")

// Wrong argument count
mem.NewArityAtLeastError("proc-name", minimum, len(args))
mem.NewArityError("proc-name", expected, len(args))

// Division by zero
&mem.DivisionByZeroError{}
----

== Design Principles

=== Dual Definition Pattern

Each Go module has a corresponding Scheme stub file:

* Go files in `pkg/core/` contain the actual implementation
* Scheme files in `core/` document the API with docstrings
* This provides language-native documentation for users

=== Modularity

Each subpackage is self-contained and only exports its `Definitions` function:

* Easy addition of new categories
* Independent testing
* Clear organization

=== Scheme Semantics

Operations follow Scheme semantics:

* Only `#f` is falsy
* Empty list `()` is truthy
* `modulo` follows Scheme sign conventions
