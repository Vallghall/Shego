== Overview

Schego is a Scheme interpreter written in Go that can be used as:

* A drop-in library dependency for embedding Scheme in Go applications
* A command-line interpreter for running Scheme files
* An interactive REPL with a TUI interface (using tview)

== Project Structure

[source]
----
schego/
├── cmd/
│   ├── schego/           # CLI interpreter executable
│   └── schego-repl/      # REPL with tview TUI
├── pkg/
│   ├── lex/              # Lexer/tokenizer package
│   ├── ast/              # AST and parser package
│   ├── atom/             # Atom interning pool
│   ├── mem/              # Memory abstraction (objects, contexts)
│   ├── eval/             # Evaluator and state management
│   └── builtin/          # Built-in procedures
│       ├── aryth/        # Arithmetic operations
│       └── cmp/          # Comparison operations
├── test/                 # Integration tests
├── docs/                 # Documentation (AsciiDoc)
├── go.mod
└── Makefile
----

make build-cli

make build-repl

./bin/schego-repl

make test

== Usage

=== As a Library

[source,go]
----
package main

import (
    "fmt"
    "github.com/Vallghall/schego/pkg/ast"
    "github.com/Vallghall/schego/pkg/builtin"
    "github.com/Vallghall/schego/pkg/eval"
    "github.com/Vallghall/schego/pkg/lex"
)

func main() {
    // Tokenize source code
    lexer := lex.New()
    tokens, err := lexer.Tokenize(`(+ 1 2)`)
    if err != nil {
        panic(err)
    }

    // Parse into AST
    parser := ast.New()
    nodes, err := parser.Parse(tokens)
    if err != nil {
        panic(err)
    }

    // Create evaluator with built-in functions
    evaluator := eval.New()
    if err := builtin.Load(evaluator.State()); err != nil {
        panic(err)
    }

    // Evaluate the program
    result, err := evaluator.Eval(nodes)
    if err != nil {
        panic(err)
    }

    fmt.Printf("Result: %s\n", result) // Output: Result: 3
}
----

== Architecture

Schego uses a pipeline architecture for processing Scheme code:

[source]
----
Source Code → Lexer → Tokens → Parser → AST → Evaluator → Result
                │                 │             │
                ▼                 ▼             ▼
           pkg/lex            pkg/ast       pkg/eval
                                  │         (evaluation)
                                  ▼             │
                              pkg/atom      pkg/builtin
                              (symbols)     (primitives)
                                  │             │
                                  ▼             ▼
                              pkg/mem ←─────────┘
                              (objects, contexts)
----

=== Design Patterns

* **Chain of Responsibility**: Both lexer and parser use this pattern for extensibility
** Lexer Chain: `ParenNode → StringNode → NumberNode → AtomNode`
** Parser Chain: `SpecialFormsNode → ListParseNode → AtomParseNode`

* **String Interning**: The atom pool stores symbols once and references them by ID
** Memory efficient: duplicate symbols share storage
** Fast comparison: integer equality instead of string comparison

* **Memory Abstraction**: Separates object representation from evaluation
** Objects: Type-safe Scheme values with coercion helpers
** Contexts: Lexical environments with nested scoping

* **State Management**: Evaluator state is separate from evaluation logic
** Global and current context tracking
** Atom pool integration for symbol resolution
** Context stack for procedure calls and let bindings

* **Modular Builtins**: Built-in procedures are organized into subpackages
** Arithmetic: `+`, `-`, `*`, `/`, `modulo`, `abs`, `min`, `max`
** Comparison: `=`, `<`, `>`, `<=`, `>=`, predicates
** Easily extensible with new categories
